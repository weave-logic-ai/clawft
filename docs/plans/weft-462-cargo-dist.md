# WEFT-462 — cargo-dist version bump schedule (v0.31 → current / v1.0+)

**Status:** planned / deferred full bump (prep only)  
**Plane:** WEFT-462 · cycle **0.8.x** · lane ws14-deployment  
**Date:** 2026-07-31  
**Related:** ADR-002, WEFT-593, WEFT-449, WEFT-464 (SBOM), release-wasi wasip2 watch

## Summary

Schedule and document a controlled cargo-dist upgrade. **Do not land a
full `cargo-dist-version` + `release.yml` regenerate in this cut.** The
ticket's original premise ("v1.0 has shipped") is **false as of
2026-07-31**; upstream latest stable is **0.32.0** (2026-05-21). A full
regen is still **risky** because `release.yml` carries the WEFT-593
hand-patch (`allow-dirty = ["ci"]`) that must be re-applied or the
empty-matrix / binary-less release failure returns.

This note is the migration plan, risk assessment, regenerate checklist,
and quarterly cadence. Minimal safe prep ships in the same commit
(runbook section + ADR-002 amendment + pin comments). The actual version
bump is a **follow-up PR** after a dry-run on a throwaway branch.

## Why a full bump is risky (now)

1. **WEFT-593 hand-patch is load-bearing.** Stock 0.31 workflow put the
   full dist-manifest (CHANGELOG bodies) into `needs.plan.outputs.val`.
   GHA secret-scan dropped the output → empty matrix → **no platform
   binaries** (v0.6.21). We slim announcement fields, expose a dedicated
   `matrix` output, refuse binary-less announce, and fail the plan job
   if `artifacts_matrix.include` is empty. See
   [`wave-0a-WEFT-593-result.md`](./wave-0a-WEFT-593-result.md).
2. **`dist generate` overwrites `release.yml`.** Any version bump that
   regenerates CI **must** re-apply the patch (or prove upstream fixed
   the job-output secret-scan issue).
3. **Actions major bumps in 0.32.0** (`attest@v4`, default action
   versions) change the generated workflow surface; diff review is
   mandatory, not optional.
4. **Release path is tag-only validation.** A green `dist plan` locally
   is necessary but not sufficient; the last empty-matrix incident only
   showed up on a real tag in GHA.
5. **0.8.x staging should not block on regen breakage.** Ticket notes
   already say: plan after gate cuts so regen does not block shipping.

## Follow-up implementation plan (when claimed)

Work on a **dedicated branch** (e.g. `chore/weft-462-cargo-dist-0.32`),
not mixed with feature waves.

### Phase A — inventory (read-only)

1. Confirm latest stable:  
   `gh release view --repo axodotdev/cargo-dist --json tagName,publishedAt`
2. Diff our pin vs latest CHANGELOG for breaking CI / config renames.
3. List every consumer of release asset **names** and installers:
   - `scripts/install.sh`
   - `docs/deployment/release.md` / `install.md`
   - Homebrew tap `weave-logic-ai/homebrew-tap`
   - Docker strategy (self-contained since WEFT-594 — lower coupling)
   - Any docs citing `weft-cli-{version}-{target}.tar.gz`

### Phase B — local regenerate (throwaway)

```bash
# 1. Install target dist CLI (match the version you will pin)
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/axodotdev/cargo-dist/releases/download/v0.32.0/cargo-dist-installer.sh | sh
dist --version   # expect 0.32.0 (or chosen target)

# 2. Snapshot current hand-patched workflow
cp .github/workflows/release.yml /tmp/release.yml.weft593-before

# 3. Bump pin only in Cargo.toml
#    cargo-dist-version = "0.32.0"

# 4. Regenerate (will rewrite release.yml to stock)
dist generate

# 5. Re-apply WEFT-593 patch (see checklist below)
# 6. Keep allow-dirty = ["ci"] until stock upstream is safe

# 7. Plan dry-run (must still see 6 matrix rows)
dist plan --output-format=json \
  | jq '{apps: [.releases[]?.app_name], n: (.ci.github.artifacts_matrix.include // [] | length), ver: .dist_version}'
# Expect n == 6 (or 6 + Windows when WEFT-483 lands)
```

### Phase C — WEFT-593 re-apply checklist

After every `dist generate`, ensure **all** of the following still hold
(search for `WEFT-593` comments in the workflow):

- [ ] **Plan job outputs** do **not** put full free-text
      `announcement_changelog` / `announcement_github_body` into
      `GITHUB_OUTPUT` / job outputs. Slim with
      `jq 'del(.announcement_changelog, .announcement_github_body)'`.
- [ ] Dedicated **`matrix`** (and discrete pr-run-mode / is-prerelease /
      publish-prereleases) plan outputs exist; builders read
      `needs.plan.outputs.matrix`, not only `fromJson(val).…`.
- [ ] **Tag plan fails** if `artifacts_matrix.include` length is 0.
- [ ] **Host/announce requires success** of `build-local-artifacts` and
      `build-global-artifacts` when publishing (skip ≠ OK).
- [ ] **Release title/body** come from files written in the host step,
      not from embedding CHANGELOG bodies in job outputs.
- [ ] Header comment in `release.yml` still documents the hand-patch and
      points at WEFT-593 + this plan.
- [ ] `allow-dirty = ["ci"]` remains in `[workspace.metadata.dist]` while
      the patch exists.
- [ ] Full plan JSON still uploads as artifact
      `artifacts-plan-dist-manifest` (secret-scan hits **job outputs**,
      not artifacts).

If 0.32+ / 1.0+ stock workflow already avoids stuffing CHANGELOG text
into job outputs **and** refuses binary-less announce, document that
proof in the follow-up result note and consider dropping the hand-patch
(and then removing `allow-dirty = ["ci"]`).

### Phase D — review + land

1. `git diff --stat` on `release.yml` + `Cargo.toml`; human review of
   action version pins and permissions.
2. PR description must include the Phase B jq output (`n == 6`).
3. Optional: open a **prerelease tag** (`vX.Y.Z-rc.N`) on the branch once
   merged to the release line to smoke GH Actions end-to-end.
4. Verify:
   - plan job: no `Skip output '…' since it may contain secret`
   - six `build-local-artifacts` jobs run (not SKIPPED)
   - platform tarballs attached; Homebrew publish not skipped for empty val
5. Update this plan status → **done** with commit SHA; close WEFT-462
   with residual follow-ups (SBOM, wasip2 fold-in) as separate items.

### Phase E — post-bump docs

- Bump version strings in `docs/deployment/release.md` ("Generated by
  cargo-dist v0.31" → new pin).
- Re-check wasip2 wording (still HP-16 / release-wasi unless proven).
- Store a memory pattern: "regen release.yml → always re-apply WEFT-593".

## Quarterly regenerate cadence

Cadence is **documented doctrine** (ADR-002 amendment + runbook), not a
calendar cron:

| When | Action |
|------|--------|
| **Quarterly** (or sooner if a security-relevant dist / Actions fix lands) | Check latest stable `cargo-dist`; open a chore PR if pin is >1 minor behind or if we need a feature |
| **After any intentional bump** | `dist generate` → re-apply WEFT-593 checklist → `dist plan` dry-run → review diff → optional rc tag smoke |
| **Never on a release-cut day** | Do not combine version bump of cargo-dist with product tag cuts |
| **After WEFT-593-class incidents** | Prefer fixing workflow hand-patch first; bump only when stable |

Owner: release engineering / whoever claims WEFT-462 follow-up.
