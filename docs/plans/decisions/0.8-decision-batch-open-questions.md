## WEFT-543 — LeWM 192-dim SIGReg latent dimensionality

### Context

Research streams and the LeWM marketing diagram pin SIGReg as an
isotropic-Gaussian `N(0, I)` manifold in **192 dimensions**. That width
binds `mesh.sensor.v1.*` wire payloads once T22 / WEFT-523 land. No
runtime crate exists yet; the diagram and page (`docs/src/app/lewm-worldmodel-rs`)
already assume 192.

Note: ticket text cites "ADR-050" from the *LeWM draft ADR batch on
`feature/lewm-worldmodel`*. In-tree **ADR-050 is Escalation Security
(CONS-003)**, not SIGReg. Do not amend ADR-050 for this decision.

### Decision

**Pin 192 as the v1 latent width** for SIGReg / LeWM wire:

| Item | Value |
|------|--------|
| `LATENT_DIM_V1` | `192` |
| Manifold | isotropic Gaussian `N(0, I_192)` |
| Health | Welford `sigreg_health`; auto-rollback `< 0.85` for 30s (per research stream) |
| Wire version | `mesh.sensor.v1` embeds dim as a field; **v2** required for dim change |

### Rationale

1. Diagram, CSS grid (16×12), and research Q2 already assume 192 — changing
   before any wire ships would only re-open design without data.
2. 192 is a practical middle ground for edge ViT-tiny / AdaLN predictors:
   large enough for multi-sensor fusion, small enough for CBOR + mesh fan-out.
3. Encoder models may later prefer 128 or 256; that is a **versioned wire
   bump**, not a silent constant change.

### Migration / version-bump policy

- Constants land in `weftos-worldmodel-core` / `weftos-sensor-pipeline-wire`
  as `pub const LATENT_DIM: u16 = 192` with wire-schema field `latent_dim`.
- Receivers **must reject** frames whose `latent_dim` ≠ local expected for
  that schema major version.
- Changing width = bump `mesh.sensor.vN` major and dual-read during rollout.
- Revisit only after encoder-model bake-off with held-out probing accuracy.

### Code

None this ticket (crates do not exist yet). Blocks WEFT-520 design assumptions.

## WEFT-171 — `ChannelHost::register_command` consumer

### Decision

1. **Keep** the trait method on `ChannelHost`.
2. **Consumer**: production `PluginHost` (daemon channel host) owns a
   **shared, host-level** command registry — not per-channel silos.
3. **Callers**: each channel plugin may call `register_command` during
   `Channel::start` for platform-native slash commands (Discord, Slack,
   Telegram BotFather). Registrations are **namespaced by channel id**
   but stored centrally so the host can list/export them.
4. **0.8.x scope**: no requirement that an in-tree channel implement
   end-to-end registration this cycle. Mocks already exercise the trait.
   First real adapter lands with Discord/Slack slash work (0.9.x).
5. **Do not remove** the surface — product still wants slash commands.

### Out of scope this ticket

Implementing Discord/Telegram/Slack slash APIs.

## WEFT-20 — `deny_unknown_fields` Config lint mode

### Decision

- **Default**: unknown JSON keys silently ignored (forward-compat; unchanged).
- **Opt-in strict mode**: env `WEFT_CONFIG_DENY_UNKNOWN=1` (alias
  `CLAWFT_CONFIG_DENY_UNKNOWN=1`) or API
  `Config::from_json_str_with_options(..., DenyUnknown::Yes)`.
- Strict mode rejects **unknown top-level** keys with a clear error listing
  the stray key. Nested forward-compat fields remain ignored unless a future
  ticket expands depth.

### Code

`clawft-types` helper + unit tests for both modes.

## WEFT-43 — `clawft-service-llm` vs `clawft-llm` consolidation

### Decision

**Keep the split.** Documented contract:

| Crate | Role |
|-------|------|
| `clawft-service-llm` | Daemon-narrow HTTP client for one OpenAI-compat endpoint (local Hermes / OpenRouter). Minimal deps; no multi-provider router. |
| `clawft-llm` | General multi-provider abstraction (native ⊥ browser), failover, retry, SSE, router. |

### Rationale

`clawft-service-llm` lib.rs already states the split. Coupling the daemon
service to the full provider stack would force browser/feature matrices into
the substrate path. Drift risk is accepted; prevent it by **not** duplicating
new providers in service-llm — new providers go to `clawft-llm` only.

### Migration

None. If streaming is needed on the daemon path, add sibling methods on
`LlmClient` rather than depending on `clawft-llm`.

## WEFT-410 — `ValidationError::UnknownMode` fate

### Decision

**Delete the variant.**

`Mode` is a closed Rust enum; serde rejects unknown wire values at parse
time. Rust-constructed manifests cannot hold an “unknown” mode without
unsafe or raw strings. The variant was unreachable dead code.

## WEFT-544 — Rotate-but-not-revoke policy expression

### Decision

**Existing action-scoped governance DSL is sufficient** — no new DSL
construct.

Canonical expression for “agent X may rotate credentials but not revoke
tokens”:

| Action | Gate action string | Policy |
|--------|-------------------|--------|
| Rotate credential | `auth.credential.rotate` | **Allow** for agent X |
| Revoke issued token | `auth.token.revoke` | **Deny** for agent X |
| Issue token | `auth.token.issue` | independent (often Allow) |

`AuthService` already gates each operation separately
(`rotate_credential`, `revoke_token`, `request_token`). A selective
`GateBackend` that denies only `auth.token.revoke` is the canonical
implementation (mirror of existing `revoke_token_denied_by_governance`
test; WEFT-544 adds rotate-allowed + revoke-denied combined case).
